# 真实测试数据 — RTX 3080 Ti 12G

> 测试日期：2026-11-14 ｜ 模型：Qwen3-0.6B（FP16）
> 环境注记：torch 2.13.0+cu130（为匹配 flash_attn 预编译 wheel 从 2.14.1 降级，
> README 的标准栈）；注意力后端 fa2 与 torch SDPA 双份实测；小算子 flashinfer 0.6.13。
> 复现：`PYTHONPATH=. python bench/bench_real.py --suite all [--attn fa2] [--cg]`
> （数据存 `bench/results/`）；负载数据说明见文末。

## 1. 端到端吞吐 / TTFT / ITL（200 token prompt，128 token 生成）

### 1a. torch SDPA 后端（eager）

| 并发 | 吞吐 (tok/s) | TTFT (ms) | ITL mean (ms) |
| ---: | ---: | ---: | ---: |
| 1 | 33.1 | 38.4 | 30.2 |
| 4 | 122.5 | 60.3 | 32.5 |
| 8 | 241.3 | 67.5 | 32.9 |
| 16 | 475.1 | 153.2 | 32.7 |

### 1b. fa2 后端（eager）

| 并发 | 吞吐 (tok/s) | TTFT (ms) | ITL mean (ms) |
| ---: | ---: | ---: | ---: |
| 1 | 45.4 | 28.3 | 22.0 |
| 4 | 164.1 | 31.8 | 24.3 |
| 8 | 325.3 | 43.0 | 24.5 |
| 16 | 651.2 | 65.7 | 24.3 |

### 1c. fa2 后端 + Decode CUDA Graph（最终形态）

| 并发 | 吞吐 (tok/s) | TTFT (ms) | ITL mean (ms) |
| ---: | ---: | ---: | ---: |
| 1 | **319.5** | 31.5 | **2.91** |
| 4 | **1179.9** | 32.0 | 3.16 |
| 8 | **2221.5** | 34.8 | 3.36 |
| 16 | **3793.9** | 61.6 | 3.77 |

**结论**：
- fa2 替代 torch SDPA：eager 全并发档位吞吐 **+37%**（conc1 33→45，conc16 475→651），
  ITL 33→24ms——paged kernel 直读页池省掉每层 gather；
- Decode CUDA Graph：单步延迟 24ms→2.9ms（CPU launch 开销被图消除），吞吐再 **+7 倍**，
  最终 conc1 319.5 tok/s / conc16 3794 tok/s；
- 三档对比即三个优化层次：正确性兜底 → kernel 效率 → launch 开销消除。

## 2. 前缀缓存（2000 token 共享前缀，逐条请求，fa2 eager）

| 配置 | TTFT (ms) | 实际 prefill tokens |
| --- | ---: | ---: |
| 无前缀缓存（cold） | 73.4 | 2016 |
| radix（cold） | 74.1 | 2016 |
| **radix（hot，命中）** | **54.7** | **1493** |

**结论**：命中后 TTFT 降低 **25.5%**，跳过 74% 的 prefill 计算（torch 后端下为 -31%，
冷启动越快固定开销占比越高，降幅略收窄）。

## 3. n-gram 投机解码（代码复读负载，greedy，K=4，窗口 3）

| 配置 | 基线 (tok/s) | 投机 (tok/s) | 加速比 | 接受率 |
| --- | ---: | ---: | ---: | ---: |
| fa2 eager | 43.7 | **151.2** | **3.46x** | 100% |
| fa2 + CUDA Graph | 323.3 | 178.0 | 0.55x（负收益） | 100% |

**结论**：
- eager 模式下重复模式负载加速 **3.5 倍**（接受率 100% 为理想负载，prompt 即重复模板）；
- **重要发现：CG 开启后投机变负收益**——投机验证步必须绕过 CG 走 eager
  （~27ms/步），而基线 decode 全走 CG（~2.9ms/步），验证步的开销超过省下的步数。
  结论：投机解码适合 eager 模式或更大模型（单步更贵时省步收益更大），
  CG 与投机需要 piecewise CUDA Graph（ROADMAP）。

## 4. KV offload / swap 抢占（32→12 块小池，2 并发互异 1400-token 前缀 × 2 波）

| 配置 | Wave1 吞吐 | Wave2（重复请求）吞吐 | 主机留档 | 主机命中 | 拉回块数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| offload 关 | 43.9 / 44.9 tok/s | （TTFT 57.8ms） | 0 | 0 | 0 |
| **offload 开** | **48.8** / **49.1 tok/s** | （TTFT 192.5ms） | 7 | 2 | 5 |

**结论**：小池压力场景 offload 开启后吞吐 +9~11%（swap 换出/换回替代 recompute）；
主机留档 7 块、二次访问主机命中 2 次、异步拉回 5 块——HBM→主机→HBM 全链路工作正常。
注：本负载下 swap 的收益被拷贝成本部分抵消（前缀复用收益未计入）；ITL 指标在此
套件中不具可比性（抢占期间不产 token，均值被低估），以吞吐与计数器为准。

## 5. 调度策略对比（32 块池 + 4×2400 token prompt + 400 token 解码，强制抢占）

| 模式 | 抢占次数 | swap 换出/换回 | 吞吐 (tok/s) | ITL P99 (ms) |
| --- | ---: | ---: | ---: | ---: |
| recompute | 2 | 0/0 | 53.7 | 44.6 |
| **swap（auto 成本模型）** | 16 | 12/12 | **61.8** | 268.3 |
| 准入 default | 2 | — | 60.1 | 43.5 |
| 准入 conservative | **1** | — | 50.4 | 43.7 |

**结论**：swap 相比 recompute 吞吐 +15%（61.8 vs 53.7），但换回延迟推高 ITL P99
（268ms vs 45ms）——吞吐换尾延迟的典型 trade-off；conservative 准入把抢占从 2 次
压到 1 次，代价是准入保守导致吞吐略降。三者各有适用场景，开关均已参数化。

## 6. W8A16 权重量化

| 指标 | FP16 基线 | W8A16 |
| --- | ---: | ---: |
| 权重显存 | 1.40 GB | **0.99 GB（-29.3%）** |
| 吞吐（8 并发） | 236.1 tok/s | 202.4 tok/s（-14%） |
| 贪心输出重合率（自然语言 prompt） | — | 89.8% |

**结论**：权重显存 -29.3%（非 -50%：embedding/lm_head/norm 保持 FP16，仅投影层量化）。
吞吐 -14%：自研 Triton dequant GEMM（固定 64×64×64 tile，未 autotune）不敌 cuBLAS
FP16——显存换时间在 0.6B 小模型上不成立（decode 受权重带宽限制的理论收益被
dequant 开销吃掉）；更大模型 / autotune 后预期改善，列入补测。

## 8. 已知问题（本次测试暴露并修复/记录）

1. **已修复**：swap 换入门槛只看 free blocks，导致 swapped 序列饿死（死锁）——
   现计入可驱逐的 cached 块。
2. **已修复**：异步拉回在途时 idle 守卫误判死锁（空转 1024 步 <0.5s 早于事件就绪）——
   restoring/swapped 非空时不再计入空闲。
3. **已修复**：OOM——每层每步重复分配 padded gather 缓冲（28×2 次/步），改为
   256 对齐的模块级缓冲复用（decode 吞吐 2.5→32 tok/s）。
4. **记录**：flashinfer 0.6.13 paged attention wrapper 在 cu130+sm86 上
   num_kv_heads>1 输出错误（fa2/triton/cutlass/trtllm_gen 四后端一致复现），
   上游问题；本机注意力走自研 fa2 / torch SDPA 后端。
5. **记录**：torch 2.14.1 与 flash_attn cu130+torch2.13 wheel 的 C++ ABI 不兼容
   （undefined symbol），torch 降级到 2.13.0+cu130（PyPI 官方 wheel 即 cu130，
   恰好与 README 标准栈一致）后 fa2 正常。
6. **记录**：3 并发 + 极小池的极端抢占风暴下仍可能触发 recompute 活锁
   （抢占-重算-再抢占循环），需"抢占预算/分批重准入"策略，见 ROADMAP。
