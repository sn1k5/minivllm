# C1 — W8A16 权重量化（在线量化 + Triton dequant GEMM）

## 目标

权重 int8 存储（显存减半），激活保持 bf16/fp16。**加载时在线量化**——不需要离线校准脚本，
`--weight-quant w8a16` 即用。

## 设计

### 量化（`src/compute/layers/w8a16.py`）

- per-output-channel absmax：`scale = amax/127`，`q = round(w/scale)` clamp 到 [-127,127]。
- 用 module 级开关 `set_w8a16_enabled()` 而非穿透构造函数参数：Worker 建模前设置，
  线性层按 int8 参数建 `weight`（int8）+ `qscale`（fp16），省掉全链路签名改动。

### 加载（`src/compute/layers/linear.py`）

四类并行层在 `weight_loader` 里"先量化整张、再按 TP 切片"：
- Column/Merged：切输出维（scale 随行切）。
- Row：整行量化后切输入维（scale 与输出通道对齐，all-reduce 后数学正确）。
- QKV：先量化 Q/K/V 各自整张，再按 shard 切行，scale 随行。
- Router gate（ReplicatedLinear）与 lm_head 不量化（精度敏感）。
- MoE 专家权重（`src/moe/experts.py`）暂不量化。

### 前向

Triton kernel：int8 tile → 转 x.dtype → 乘 per-row scale → `tl.dot`，fp32 累加，
固定 tile 64×64×64、4 warps（可读性优先，未上 autotune）。

## 用法

```bash
python run.py --weight-quant w8a16 --prompt "你好"
```

## 验证

- 数值：小矩阵对照 `F.linear(x, w.to(torch.float16))`，相对误差应 < 1%（per-channel 量级）。
- 端到端：Qwen3-0.6B greedy 输出与 bf16 版逐 token 对比，前 N 个 token 重合率。
- 显存：`torch.cuda.memory_reserved` 对比权重占用减半。
- 性能：decode 阶段 W8A16 GEMM vs cuBLAS fp16 的单步延迟（小 batch decode 受权重带宽限制，
  int8 应占优）。
