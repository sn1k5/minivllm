# E2 — 缓存感知路由（智能节点选择）

## 目标

多实例部署时，把请求路由到"最值得"的实例：**前缀缓存命中多的、队列短的、KV 水位低**的优先。

## 设计

| 文件 | 职责 |
| --- | --- |
| `src/serving/router.py` | 实例探测、打分、选主 |
| `serve_router.py` | 路由进程（FastAPI 反向代理） |

打分（规则版，权重可配）：

```text
score = w_prefix * (matched_tokens / prompt_tokens)
      + w_queue * (1 - waiting / max_num_seqs)
      + w_kv    * (1 - kv_usage)
最终得分 = score × instance_weight，取 argmax
```

- `matched_tokens` 来自各实例 `/internal/prefix_probe`：实例侧用自身前缀索引做**只读探测**
  （`KVManager.probe_prefix_len`），不分配页、无副作用。
- 队列与水位来自 `/internal/stats`。
- 失败实例本轮跳过，全挂返回 503。
- `/router/stats` 展示各实例最近一次打分明细，方便观察路由决策。

## 用法

```bash
# 起两个引擎实例
python serve_api.py --port 8001 &
python serve_api.py --port 8002 &
# 起路由
cat router.yaml <<EOF
instances:
  - {url: "http://127.0.0.1:8001", weight: 1.0}
  - {url: "http://127.0.0.1:8002", weight: 1.0}
weights: {prefix: 0.5, queue: 0.3, kv: 0.2}
EOF
python serve_router.py --config router.yaml --port 8100
```

## 验证

- 同一长 system prompt 打两轮：第二轮应稳定路由到同一实例（命中驱动）；
- 一个实例灌满队列：新请求应落到另一实例（水位驱动）；
- 对比轮询路由与打分路由的 prefill token 节省与 P50 TTFT。
